The bounded reproducer at `/home/afterburner/.local/state/pigade/soak/resize-repro-20261017` ended after 1013.162 seconds with `input ACK timeout: SOAK-0-196`. The last resize-admission snapshot was at 984.189 seconds and showed stream 0 running at sequence 17925 with no storage error.

A read-only scan validated the retained journals' framing and CRC through EOF. Stream 0 contained one `ACK:SOAK-0-195`, no `ACK:SOAK-0-196`, and 20,133 output bytes in 85 output events after ACK 195. The journal continued to sequence 18065 (17,738 output and 327 resize events) and ended in output, without an Exit event. This excludes a mere frame-text visibility miss for token 196, but does not say whether input was still queued, the child had not read it, or its ACK write was stalled before journal append. Journal records have sequence numbers but no event timestamps, so the last tail cannot be timed against the harness admission clock. Cumulative fsync/checkpoint durations do not identify the blocking stage.

The harness now writes two bounded diagnostic artifacts on the next ACK timeout. `ack-timeout.json` records the PING IPC admission outcome, monotonic request times, the unchanged five-second timeout, last state/sequence/storage-error for each stream, snapshot duration and completion monotonic time, and a target-token-visible boolean only for the target stream. Other views may be stale; their snapshot ages are included. It also records wait-channel metadata from `/proc`: host plus at most 32 threads, and each child, with state, `comm`, `wchan`, and start ticks. It revalidates boot ID and process start identity before and after reads and verifies each sampled thread's start ticks. Failed or changed identities yield a diagnostic error instead of data. It does not collect stack traces, command lines, environment, terminal frames, or text.

`ack-producer-sidechannel.jsonl` records synthetic producer milestones (`ping_received`, `ack_write_completed`, and `release_observed`) with stream, token index, monotonic timestamp, and per-producer event sequence. Datagrams are fixed-size, the file is capped at 16,384 rows with an omitted counter, and each drain processes at most 512 packets. The producer advances the sequence once per valid milestone send attempt, including a failed datagram send, so a later received event exposes the count of missing middle events. A missing first or last packet may only appear as an incomplete lifecycle. This sidechannel is outside the durable terminal journal and contains no input payload. It changes neither output bytes nor ACK/RELEASE protocol; it can lose a milestone if the local datagram queue fills.

A focused real-PTY regression verifies the three milestones and exact token identity. The evidence is diagnostic: comparing producer milestones, host sequence/state, snapshot duration, and wait channels should distinguish child-side waiting from publication lag. `/proc` samples are not atomic snapshots, and a wait channel is a point-in-time hint; neither alone proves root cause.
