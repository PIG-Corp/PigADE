# Native EN/RU and CLI keyboard — 0.0.1-dev

The actual release application receives a fixed31-byte EN/RU/CLI sequence
exactly once in private Xvfb. The probe found and repaired real Alt-printable
input loss: GPUI's pinned X11 and Wayland window handlers only generate default
text insertion for a subset of Shift modifiers. PigADE previously waited for a
text commit after Alt+X, so neither ESC nor x reached the PTY.

Alt with actual printable layout text now encodes ESC plus that UTF8 text in
the key event. The existing Bytes path stops propagation, preventing a second
default insertion. Ordinary EN/RU/IME text still uses committed text; a dead
key without committed text is not guessed. Controls and the16KiB atomic input
limit remain enforced. The focused regression first failed with
`PlatformText { meta: true }` instead of `[27,120]`, then passed after the fix.

The fixed native sequence is `ab1Z`, Ctrl-C/D/Z/R/L/A, Alt-x, Left, Home, Enter,
and `привет`. A pinned test-only setxkbmap loads requested layouts us,ru before
app startup. The identity-gated helper switches group indices0/1, reads back
XKB state and checks no modifiers/keys remain held. It does not read back layout
names. [XKB's primary documentation](https://www.x.org/releases/current/doc/libX11/XKB/xkblib.html)
distinguishes the one-way group request from the synchronous state query.

The raw/no-echo PTY child verifies exact bytes/hash and absence of trailing
bytes before emitting an unrelated ACK. Baseline appb4d63952… twice received29
bytes, missing only ESC+x. Fixed appf9fea286… receives31 bytes, extras0, with
visible child ACK. This build also includes the independently tested command
failure gate; the pure regression isolates the Alt encoder change. The same
fixed app subsequently passes native Pinyin again: no bytes before commit,
exactly6 UTF8 bytes for你好 after Space, extras0. Root inspected keyboard ACK
and Pinyin preedit/final PNGs. The native candidates appear in Fcitx's popup.

[Source-bound artifacts](../../crates/app/evidence/keyboard-20261017/) retain
both failures and passes, source/executable/helper/SDK/font hashes and PNGs.
The same namespace, Xauthority, socket/peer/XRes/app-focus guards from the
[X11 IME report](x11-ime-20261017.md) apply; the user's desktop is inaccessible.
This is one synthetic software-rendered X11 key sequence, not all shortcuts,
physical keyboard hardware, Wayland runtime, all locales, clipboard, native
composition target barriers or cross-platform certification.

Fresh98 app tests and strict Clippy passed; release build and formatting pass.
Python129 discovered tests include16 harness tests, with real raw-PTY checks
for fixed keyboard/IME bytes and deliberate trailing duplicates. No deadline
or terminal output semantics changed.
