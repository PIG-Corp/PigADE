# Actual X11/XIM Pinyin probe — 0.0.1-dev

The actual PigADE app now passes one native Fcitx-Pinyin Unicode commit in debug
and release inside private Xvfb. This closes a concrete XIM focus defect in the
pinned GPUI backend; it does not complete the Linux input/platform gate.

## Fixture and evidence

The harness creates fresh mount/PID/user/IPC/network namespaces, private HOME,
Xauthority/runtime and D-Bus without service activation. Host displays, session
buses, provider homes, GPU/input nodes and external network routes are absent.
Before fixed XTEST keys, it checks namespace differences, Xvfb boot/PID/start,
socket owner/inode and SO_PEERCRED, XTEST availability, unique XIM selection
owner through XRes, and app window ownership through both XRes and_NET_WM_PID.
A separate focus-only step precedes private Pinyin selection/activation. No
keys or focus operations run on the user's desktop.

Fcitx5.1.23/Pinyin5.1.15, Xvfb21.1.25 and the software renderer come from pinned
signed test-only Arch archives (13 X11 packages plus2 renderer packages).
Signatures, primary signers, archive hashes, package identity, addon dependencies
and16 dynamic-link checks are retained. GPL Pinyin is a test component, not a
PigADE product dependency. Host /usr libraries participate; this is not a
portable self-contained sysroot or hardware-GPU test.

The raw/no-echo PTY child reports READY over a private control channel. The
helper types fixed `nihao`; the child confirms no input before commit and the
host cells remain unchanged. After fixed Space, it receives exactly6bytes,
matching UTF8你好, waits for extras, confirms none, and emits a unique ACK not
present in the submitted text. The actual app displays that ACK and exited
state in the release capture. Root inspected baseline, preedit and final images.
The native preedit/candidates appear in Fcitx's bottom-left popup; this run does
not prove inline GPUI composition or correct caret anchoring.

[Source-bound artifacts](../../crates/app/evidence/x11-ime-20261017/) include
baseline/failed attempts, exact app/host/helper/SDK/font hashes, patch profile,
namespace/identity evidence and PNGs. Baseline app0cecf217… (product source33bd5dd,
clean upstream GPUI) renders after5s fixture settle but returns empty current IM.
With only the tracked GPUI focus profile added, debug appdc010945… and release
appb4d63952… pass. Host9c22265d… is unchanged. The5s settle is not a startup
latency result. The initial debug final screenshot preceded the UI ACK update;
the release harness waits250ms after host ACK and captures the visible result.

## Retained failed attempts and corrections

- Initial namespace startup exited without stderr retention; reason was unknown.
  After adding bounded stderr, the next attempt exposed a bind onto an XKB
  symlink. Bind its resolved read-only data directory and pinned xkbcomp binary.
- Xvfb crashed with a stack entering host Nvidia EGL/GLX libraries. Disable the
  unneeded GLX extension for this Vulkan/software fixture and create the private
  X socket directory. The exact underlying driver defect was not diagnosed.
- The XIM root property is `XIM_SERVERS`, not `_XIM_SERVERS`; the server selection
  atom is `@server=fcitx`. XRes wire length4bytes decodes to one CARD32 PID.
- The private Fcitx profile lacked required `Default Layout=us`; pinned source
  confirms such groups are skipped. The SDK initially omitted Pinyin's required
  punctuation addon; extraction-profilev2 includes/checks its files.
- After those corrections and a real rendered/focused app, baseline still had
  no current IC. [ADR0010](../adr/0010-gpui-x11-ime-focus-lifecycle.md) records the
  actual product patch and its lifecycle tests. Earlier environment failures
  are not evidence against the product focus lifecycle.
