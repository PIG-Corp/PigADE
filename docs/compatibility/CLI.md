A resume adapter must bind a concrete conversation through documented structured events or explicit user binding, preserve cwd/revision, never use `--last`, and never fall back to a new conversation after resume failure.

- [Claude CLI reference](https://code.claude.com/docs/en/cli-reference): interactive launch, exact resume and session-scoped instruction flags. Current docs can describe versions later than the installed binary; help alone does not certify behavior.
- [OpenCode CLI](https://opencode.ai/docs/cli/) and [agents](https://opencode.ai/docs/agents/): session selection and documented role configuration. Actual adapter tests remain required.

Manual OpenCode1.19.3 uses only `--session <exact ID>`, never `--continue`, `--fork`, a positional task or `--prompt`. The source plan must be context-off. PigADE does not resend a task, transfer provider credentials or parse provider-owned databases. Binding is manual; it is not automatic conversation discovery.

OpenCode's stored session directory can override process cwd through native routing. The adapter therefore requires a fresh public `GET /session/:id` metadata check before both PrepareResume and StartPrepared: exact ID, canonical stored directory equal to source cwd, and no workspaceID. An authenticated pure server binds literal127.0.0.1 with a random port and child-only credentials; a child-only random workspace override forces its probe onto the source-version's local routing branch, so metadata cannot proxy to another workspace. Startup/output/HTTP budgets are finite; all outcomes terminate/reap its own process group, and Linux parent-death handling closes orphan startup. The dedicated single-worker/one-waiter queue returns to the command actor with an internal-only receipt and revalidates binding, exited generation, plan, executable and directory device/inode/canonical path. Neither the internal receipt nor its authority can be supplied by IPC JSON. Other terminal commands remain available during the probe. Unknown or previously attempted launches retain existing durable locks.

Inherited `OPENCODE_CONFIG_CONTENT` or `OPENCODE_WORKSPACE_ID` disables advanced OpenCode capabilities while preserving ordinary CLI launch and reported version. Their values are not copied or logged. Native workspaces, unknown versions and startup-context delivery remain unsupported. Metadata/directory checks are preflight observations, not locks against later external filesystem/provider-state mutation; native CLI still validates the selected ID at startup. Previous-version, reboot, account-mismatch and complete provider acceptance remain open.
