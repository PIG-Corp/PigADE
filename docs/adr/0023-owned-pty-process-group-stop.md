# ADR0023 — Stop the owned PTY process group

Status: accepted for 0.0.1-dev, Linux only; full platform/MVP gates remain open.

BridgeMind's terminal lifecycle exposes explicit session termination separately from hiding a pane and closing the UI. PigADE already binds Stop to one session/generation and requires confirmation, but portable-pty0.9.0's Unix `ChildKiller::kill` signals only the child PID, waits up to200ms and may reap it. An ordinary same-group child that ignores SIGHUP can remain alive and hold the PTY open. Reusing a saved numeric PID after reap would also be unsafe.

The actor now owns one `GroupStop` beside its exclusively owned, unreaped Child. The existing authenticated launch captures boot ID, PID and start ticks before permitting helper exec; the helper execs CLI in place. The pinned portable-pty Unix spawn calls setsid, initially making PID=PGID=SID. Stop sends one SIGHUP to that original process group, waits at least200ms using the actor's receive deadline, then attempts one SIGKILL. It never sleeps through grace or waits for child completion inside the signal helper. Ordered output/resize/model publication continues; other actors and the host command loop remain independent. The deadline is process control, not a terminal-model timer or a replayable external effect.

Immediately before each signal, the helper checks frozen identity, PID>=2/pid_t conversion, PGID=PID and SID=PID, and refuses the host's own PID/group/session. Identity read failures fail explicitly, including missing boot ID. Signal/getpgid/getsid ESRCH is benign absence, other failures latch without retry. Duplicate requests neither resend signals nor extend grace. No numeric group signal is sent from recovered metadata or after reap. EOF cannot call try_wait during grace, even when the leader has already exited and all slaves are closed. After successful try_wait, disarm permanently prohibits signaling; a later Stop on a degraded/reaped actor reports unavailable. Degraded storage handling uses the same timer/control path without publishing an invented durable Exit.

Before each signal the helper also reads (never changes) the host SIGCHLD disposition and refuses SIG_IGN, SA_NOCLDWAIT or any non-default handler: auto-reaping or an unknown reaper would invalidate exclusive unreaped-child ownership. The host source has no competing global reaper and does not mutate this policy while actors run.

The unreaped child is essential: an exited direct child remains a zombie and retains its PID until wait removes it. The group target cannot be selected merely because a stored PID or process name matches. The host never calls portable Child::kill in this actor Stop path, since that implementation can reap between signals. Handshake-timeout cleanup remains separate and cannot have executed the provider yet.

Wire requests and storage/journal schemas are unchanged. New runtime Views advertise stop_scope=`pty_process_group_v1`; omitted/unknown scope keeps a conservative confirmation in old-host connections. Stop failures are optional stop_error metadata, distinct from storage_error and included in poll watermarks, bounded to1024 UTF-8 bytes by the producer. UI freezes the target scope, retains exact-generation failure/inspection state, never resends on a lost response, and treats confirmed exited as absorbing. Closing/reopening the sheet does not retry. A reopened UI can inspect an already reported failure without fabricating a Stop request. UI restart/host recovery does not restore signal authority.

Scope is deliberately one original process group, not the whole session or an arbitrary descendant tree. A CLI may create another job-control group or detached session; these are not covered. There is no cgroup/process-tree enumeration, recursive kill or new platform claim. Confirmation states this limitation. A durable exited frame proves the main CLI ended; it does not prove every detached descendant ended or that the CLI flushed user files successfully.

Evidence and API semantics: [Linux kill(2)](https://man7.org/linux/man-pages/man2/kill.2.html), [setsid(2)](https://man7.org/linux/man-pages/man2/setsid.2.html), [getpgid(2)](https://man7.org/linux/man-pages/man2/getpgid.2.html), [getsid(2)](https://man7.org/linux/man-pages/man2/getsid.2.html), [waitpid(2)](https://man7.org/linux/man-pages/man2/waitpid.2.html), and the [exact portable-pty0.9.0 Unix source](https://docs.rs/crate/portable-pty/0.9.0/source/src/unix.rs). Zombie getpgid/getsid behavior is verified by the real-host tests on the actual Linux environment, not inferred as cross-platform parity.

`tests/process_group_stop.rs` exercises HUP-ignoring leader/descendant, naturally exited unreaped leader, and HUP leader exit plus immediate PTY EOF. It also checks another live generation, saved output/durable Exit, full replay and host reopen. Cleanup uses identity-rechecked pidfds and never a post-check numeric PID signal. Existing slow-input and checkpoint actor tests cover backpressure and actor serviceability. The existing isolated catalog fixture covers native confirmation/cancel/complete and hidden-session Stop; measured results belong in the handoff/WORKLOG, not an assumed completion claim here.
