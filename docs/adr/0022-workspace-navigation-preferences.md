# ADR0022 — workspace switching and local navigation preferences

Status: implemented for Linux 0.0.1-dev; verification is recorded in the agent handoff.

BridgeMind's workspace registry makes parallel tasks discoverable. PigADE already owns the project/workspace/tab hierarchy and host selection CAS. Its previous workspace action always picked the first tab, losing the user's place, and the sidebar could only expand every project. The new optional switcher adds searchable current/recent destinations and local folding, without another terminal runtime or a database schema change.

Selecting a ready workspace uses the existing selection CAS. A current valid tab wins over a remembered tab; otherwise the remembered ID must still belong to that exact workspace, with the first existing tab as fallback. Empty workspaces stay empty. Non-ready entries lead to management. Switching neither executes a program nor rewrites tab layout JSON, generation pins or canvas geometry. The first confirmed selection establishes a local baseline; a changed confirmed workspace/tab tuple updates recency. Ordinary catalog refresh, focus or rename cannot make an unchanged tuple recent again. Late refresh replies preserve the search/draft; a late selection reply cannot dismiss a newer editor.

Preferences are scoped to the exact host socket bytes and contain only up to32 distinct workspace/tab UUID pairs and128 collapsed-project UUIDs. No paths, terminal output, prompts, provider history or authorization are persisted. Private bounded schema1 JSON, a per-file lock, semantic operation merge and atomic file/directory sync preserve independent windows' changes. Unsupported/malformed/symlink/foreign/oversized files are preserved. A single background writer with bounded coalescing accepts explicit SetCollapsed/Visit operations; unchanged receipts do not write, errors retain local intent and expose explicit retry/reload. Window close waits through the existing save coordinator. Concurrent windows merge on the next operation or explicit refresh; they do not run a new filesystem watcher.

Workspace rows cache by catalog/config invalidation and search-buffer revision. Building rows indexes projects/tabs rather than rescanning all tabs per workspace; frames do not repeat the search. Search covers project, task and path. Stable selected UUID survives a reorder/refresh, and mouse/keyboard use the same eight-row pages. The previous ready recent workspace is initially selected, while query changes filter the registry. Escape before choosing does not change host selection. Prefix,A and the breadcrumb open the sheet; Alt+Left/Right fold the chosen row's project without changing the active workspace. Ordinary CLI Ctrl shortcuts are unaffected.

The startup path also recognizes typed `host_shutting_down` receipts and the socket-missing/endpoint-lock-held interval. It waits a bounded six seconds for the same validated endpoint lock to release and reprobes before creating a host. Explicit sockets remain untouched, a healthy endpoint is reused and the ordinary readiness deadline remains three seconds. No signals, lock-file creation/unlink for probing, CLI retry or native conversation resume is introduced.

Tests cover MRU/tab reopen, cross-window preference merge, source preservation, deleted/foreign tab fallback, stable selected IDs, exact stopping receipts and missing-socket lock release. Native verification extends the existing isolated setup flow; additional platforms, full accessibility/IME and the remaining terminal release gates are independent work.
