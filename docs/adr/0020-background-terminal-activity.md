# ADR0020 — background terminal activity without hidden cell replicas

Status: implemented for Linux 0.0.1-dev; native verification is recorded in the handoff.

BridgeMind's attention surface separates an unread notification from an approval or a successful task. PigADE needs to surface background terminal output and process exits while retaining its existing bounded visible-frame subscription. Idle output is not evidence that an agent is waiting.

The existing Poll, PollVisible and PollPanels replies carry an optional schema1 `activity` snapshot: the sampled host incarnation/revision and at most32 exact authoritative generation heads. Each entry contains session/generation IDs, published sequence, durable published output-byte count, process state and a storage-error bit. It contains no cells, terminal text, titles, input or provider secrets. Resize and timer events do not increase the output count. No new polling thread, parser, command, SQLite migration or automatic host restart is introduced. Missing activity on older hosts disables this surface. Malformed activity disables only its own indicators; valid terminal frames still apply.

The token is sampled before metadata reads. Its revision is a wake hint, so equal revisions can contain forward per-session watermarks; regression is rejected without changing the last good tracker. The first connection establishes a baseline. A new host incarnation establishes another baseline instead of replaying historical notifications. Within one incarnation, matching persisted read watermarks retain unseen changes across UI reopening. New process generations have independent watermarks. One bounded entry per current session coalesces repeated output and lifecycle observations; there is no unbounded event queue.

Tabs and workspaces count unique unread sessions. A compact activity sheet lists output, actual CLI exit and storage failures, with actions to open the existing placement or mark the exact generation viewed. Archived placements lead to workspace management; unplaced sessions remain accessible through Sessions. Opening a destination neither starts a CLI nor changes a pinned generation. Consequently a historical pinned view does not clear a newer head's activity. Marking viewed grants no approval, sends no input, and makes no claim about task success. OS notifications, sound, bells, waiting-for-approval signals and a durable notification timeline are not implemented by this slice.

Automatic acknowledgement happens only for an exact current-generation frame submitted by the canvas painter in an active window, without a modal, drag or resize, and outside historical browsing. The published summary sequence must not exceed that painted frame and lifecycle/error state must match. Merely receiving metadata, switching tabs or showing a sheet is not a read. This is a functional read-receipt policy, not proof of physical GPU presentation.

Read receipts contain IDs/counters/state only. Their bounded32KiB schema1 file is scoped to the chosen host socket under the PigADE config directory. Atomic private temporary files, file/directory sync and a bounded advisory lock protect writes. Same-incarnation saves merge acknowledgements for exact generations; the newer observed head-set revision prevents a stale window replacing a newer generation. Separate host sockets have separate files. A single worker has one in-flight save and the latest UI intent, with a one-second cadence; resize-only sequence changes do not write receipts. Window close includes pending receipts in its existing flush coordinator. File failures are visible and require an explicit retry; malformed files are preserved. Concurrent windows merge on disk but do not synchronize their in-memory read status live.

Badge counts are cached by layout revision and the sorted unread session set, parsing each tab layout once per cache change. Hidden output does not cause full terminal-frame cloning or change PTY geometry. Tests cover metadata/head bounds, output-versus-resize, duplicate and same-token observations, generation changes, stale paints, host replacement, persistence/reopen, malformed files and optional-protocol failures. Native verification uses the existing private controls fixture; no active-desktop automation is authorized.
