# GPUI X11 IME focus patch

This profile v3 targets GPUI commit `322cd509dcccaee1f6bc44725d270598ae8171ad` and the exact upstream archive SHA-256 recorded in `manifest.json`. `focus.patch` changes only `xim_handler.rs`, `client.rs`, and `window.rs`; it adds no upstream files or dependencies. The XIM focus lifecycle from v2 is unchanged. This version also fixes the `XdndAware` property type: this pinned GPUI revision interns `XA_ATOM` as a custom atom name because its atom table does not define the standard `ATOM` alias. The setter now uses XCB's predefined `xproto::AtomEnum::ATOM`, as required for the property type. The profile verifier asserts the builtin atom is used and prevents regression to the custom `XA_ATOM` symbol.

The v3 `previous_files_sha256` values identify the exact v2 postimages, allowing the patch applier to migrate an already-patched verified cache. The XIM handler postimage remains byte-identical to v2. In addition to the `XdndAware` correction, the client now reads at most 64 KiB of X11 selection data and rejects a truncated or malformed URI list as a whole; it ignores empty and comment lines and emits an empty external-path event on invalid data so the application can report the rejected drop without accepting a partial list. This bounds the transport for the application’s larger encoded path payloads. The upstream commit and archive remain pinned, and applying the profile still requires exact preimages/postimages.

The X11 drag state marks a drop successful only after a complete, nonempty list of file URIs has been decoded. Invalid, truncated, or empty lists still produce an empty-path event for the application-level rejection message, but `XdndFinished` reports failure and a zero action; valid nonempty file lists report success with `XdndActionCopy`. A fresh `XdndEnter` clears the prior result. The isolated fixture asserts the failure result for malformed and oversized URI-list payloads.

The window input-modality classifier also treats file-drop `Entered`, `Pending`, and `Submit` events as mouse input before GPUI translates them into internal mouse-move/up events. This matters after Escape leaves the window in keyboard modality: hitbox hover tests otherwise suppress the stationary cursor, and an outside mouse-up capture can consume the translated drop before the root drop listener sees it. File-drop `Exited` and `Ended` preserve the current modality. Ordinary repaints still do not switch keyboard navigation back to mouse modality.

The focus lifecycle separates input-method readiness, desired X window focus, and the IC lifecycle. It defers IC creation until both the IM is ready and a nonzero focused window exists, creates at most one IC at a time, and waits for DestroyIC reply before replacing an IC bound to a different window. A late CreateIC reply is destroyed if its original window is no longer the desired focus. Focus is requested only after CreateIC reply and only while its original window remains focused. FocusOut queues UnsetICFocus before ResetIC; same-window refocus reuses the existing IC. XIM key forwarding and commit/preedit/forward-event callbacks are gated on the currently focused IC ID, not merely the active window or an older IC. Failed SetICFocus submission clears local focused state; failed unset/reset/destroy requests never make an IC eligible for forwarding or callbacks.

The pinned xim-rs dependency receives an additional, separately hash-pinned `xim-preedit` patch that sends the required `PreeditStartReply` after a successful start callback and sends no reply after a failed callback. SetICFocus and UnsetICFocus are one-way XIM requests, so “focused” means the request was successfully sent in order on the XIM connection; the protocol provides no server acknowledgement for either operation. This profile does not certify composition reset/generation barriers, server failure recovery, or other XIM styles. Preedit spot-position behavior remains driven by GPUI's existing `update_ime_position` path and has not been measured by these pure state tests.

The [XDND specification](https://www.freedesktop.org/wiki/Specifications/XDND/) requires the predefined `ATOM` property type for `XdndAware` and uses `text/uri-list` for file transfers.

Run `python3 scripts/test_gpui_xim_focus.py` to check archive/preimage hashes, apply the exact patch in a temporary directory, verify postimage hashes, the builtin `XdndAware` atom type, and file-drop modality handling, extract the embedded state tests, and execute them with `rustc --test`. This is a no-GUI check; it does not prove live XIM or drag-and-drop behavior. The root integration owner must apply the profile and run the pinned app build plus isolated IME fixture before making a product-level claim.
