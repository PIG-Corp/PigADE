# PigADE

**PigADE — Agentic Development Environment:** настольная среда для работы с несколькими CLI-агентами в одном проекте.

```text
Проект: общий Git-репозиторий и связанные части продукта
└── Воркспейс: задача, агенты, общий промпт, роли и память
    └── Вкладка: сохранённая раскладка
        └── Панели: Claude Code, Codex, OpenCode, shell и другие CLI
```

Текущая версия: **dev 0.0.1** (`0.0.1-dev`, [VERSION](VERSION)). В native UI доступны Git-проекты, воркспейсы в общей папке или отдельном worktree, вкладки, запуск shell/Claude Code/Codex/OpenCode, палитра команд и редактор версий контекста. Раскладка хранится в host: split, направленный focus/move/swap, перенос между вкладками и воркспейсами, resize с preview, focus mode и undo/redo. Изменение раскладки не запускает новый процесс. Перед запуском доступен просмотр неизменяемого итогового контекста, роли, явно выбранной памяти и метода доставки. Для Claude Code 2.1.259 и Codex 0.162.1 реализованы параметры запуска с контекстом; подтверждение применения моделью отсутствует. OpenCode и неизвестные версии доступны через явный запуск без контекста. Снимок и результат попытки сохраняются для конкретного поколения сессии; редактирование общего документа не меняет работающую сессию. Готового MVP и Linux beta пока нет; оставшиеся критерии SPEC не ослаблены.

## Что уже можно проверить

Native Rust host запускает реальные процессы через portable-pty. Единственная модель alacritty/VTE находится в host; output/resize/timer events получают sequence и generation, сохраняются с CRC и fsync до публикации клеток. Есть bounded очереди, отдельный input writer, private Unix IPC, durable launch intent/helper/OS identity gate и блокировка неизвестного исхода запуска. После потери host восстановление историческое; процессы и задания сами не повторяются.

Экспериментальный полный checkpoint объединяет Term/Grid и parser/processor: оба экрана, горячую историю, курсоры, modes, tabstops, цвета, частичные UTF-8/CSI/OSC, synchronized buffer и логический timer. Host также архивирует вытесненные строки normal screen как производные записи PIGROW02 в поколенческие сегменты с фиксированным индексом; PIGCP002 привязывает только fsync-подтверждённый индексный корень. Журнал остаётся источником восстановления и не удаляется. Полное восстановление сравнивает горячую модель/parser и каждую холодную запись. Это реализованная основа, а не приёмка длинной истории: текстовый просмотр со страницами и поиском реализован; квоты, глобальный heap budget и long-history gate ещё не завершены.

Нечитаемые или несовместимые журналы показываются отдельным предупреждением восстановления. Они не создают фиктивных живых панелей и не блокируют ввод в исправные сессии. При повреждении типизированного хвоста сохраняются последний корректный кадр и его sequence; исходные файлы остаются без изменений.

[Приложение PigADE](crates/app/README.md) использует GPUI и получает клеточную реплику Rust host. Собственного ANSI-парсера в UI нет. Отдельные контрольные приложения удалены по решению пользователя; история раннего сравнения сохранена в Git. Это рабочее направление разработки, с открытыми gate корректности и платформенной поддержки.

## Сборка и проверки

Проверенная среда: Linux x86_64, Rust/Cargo 1.98.1, C compiler для bundled SQLite. Для UI нужны системные библиотеки GPUI из его официального Linux setup. Другие compiler/distro/platform версии не сертифицированы. Cargo.lock в корне и crates/app/Cargo.lock фиксируют зависимости host и UI. Лицензия продукта пока не выбрана; лицензии vendored компонентов сохранены, GPL terminal-код Zed не заимствован.

```sh
cargo build --release --workspace --bins --examples
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
python3 scripts/check-version.py
```

Для UI: `crates/app/bootstrap.sh build --locked` и `crates/app/bootstrap.sh test --locked`. Bootstrap проверяет SHA-256 закреплённого GPUI archive и применяет [точный профиль X11 IME](crates/app/patches/gpui-x11-ime/) с проверкой исходных/итоговых хешей; неизвестное состояние кэша останавливает сборку. Он только собирает код, без открытия окон. `bash scripts/check.sh` выполняет проверки host/model workspace. Полные vendor/regression-команды и фактические результаты находятся в patch notes и отчётах.

## Запуск Rust host

Без systemd, в отдельном терминале:

```sh
mkdir -p "${XDG_STATE_HOME:-$HOME/.local/state}/pigade/dev-0.0.1"
target/release/pigade-session-host serve "${XDG_STATE_HOME:-$HOME/.local/state}/pigade/dev-0.0.1"
```

Управляемый user service, отдельный от UI:

```sh
bash scripts/start-dev-host.sh
systemctl --user status pigade-dev-host
```

Пример реального shell в host:

```sh
target/release/pigade-session-host launch \
  "${XDG_STATE_HOME:-$HOME/.local/state}/pigade/dev-0.0.1/host.sock" \
  "$PWD" /usr/bin/bash --noprofile --norc
```

Для длинного пути состояния можно указать отдельный короткий приватный каталог: `serve STATE_DIRECTORY --runtime PRIVATE_DIRECTORY`. Каталог runtime должен принадлежать пользователю и иметь режим 0700; UI подключается к `PRIVATE_DIRECTORY/host.sock`. Блокировки состояния и runtime предотвращают замену endpoint другого работающего host. Данные остаются в STATE_DIRECTORY.

`list SOCKET`, `request SOCKET JSON_COMMAND`, `replay JOURNAL` и `verify-recovery JOURNAL` — диагностический интерфейс. Input/resize/stop требуют точные session/generation UUID. `replay` не исполняет команды и terminal side effects. `verify-recovery` сравнивает полные модели полного replay и checkpoint+tail; нужен завершённый или неизменяемый журнал. Историческая панель не принимает ввод. Версия: `target/release/pigade-session-host --version`.

Остановка user service завершает его дочерние процессы; это отдельное явное действие: `systemctl --user stop pigade-dev-host`. Закрытие UI отличается от остановки host. После сбоя неизвестные launch intents остаются заблокированы; автоматического нового shell/resume нет.

## Измерения и ограничения

```sh
python3 scripts/hardware-manifest.py
python3 scripts/run-component-benchmark.py \
  --directory "${XDG_STATE_HOME:-$HOME/.local/state}/pigade/benchmarks"
python3 scripts/probe-cli-pty.py \
  --directory "${XDG_STATE_HOME:-$HOME/.local/state}/pigade/probes"
```

Benchmark требует durable filesystem, отклоняет tmpfs и измеряет компоненты без GPU/UI; его числа не равны input-to-present. CLI probe запускает только `--version`/`--help` через реальный PTY, не выполняет AI-задачи и не сертифицирует resume. Нагрузочная проверка: `python3 scripts/stress-pty.py --directory /absolute/durable/path`. Она не открывает UI и не является input-to-present benchmark. [Текущий отчёт о проверках](docs/reports/verification-0.0.1-dev.md) содержит результаты и точные пробелы.

Сырые результаты: [benchmarks/results](benchmarks/results), [CLI matrix](docs/compatibility/CLI.md), [ADR](docs/adr), [отчёты](docs/reports).

После сборки host и UI приложение запускается как `crates/app/target/debug/pigade-app`: оно подключается к локальному host или запускает его самостоятельно. Состояние хранится в `${XDG_STATE_HOME:-$HOME/.local/state}/pigade/dev-0.0.1`, сокет — в приватном подкаталоге `${XDG_RUNTIME_DIR}` либо рядом с состоянием. `PIGADE_HOST_BINARY` позволяет явно выбрать бинарник host. Явное подключение без автоматического старта: `crates/app/target/debug/pigade-app /absolute/state/host.sock`. Закрытие окна не завершает host. Автоматизация окон/ввода на активном desktop запрещена; platform tests требуют изолированного compositor/VM.

Редактор контекста поддерживает курсор, выделение мышью и Shift+стрелками, навигацию по словам, копирование/вырезание/вставку и ограниченный undo/redo. Enter добавляет строку в многострочном поле; Ctrl+Enter сохраняет ревизию или подтверждает запуск. Tab/Shift+Tab переключают поля. Режим PigADE, затем `E` открывает контекст воркспейса, `Shift+E` — проекта. Ответ на сохранение сохраняет набранный после отправки черновик; незавершённый IME-ввод не попадает в запуск.

Перед запуском можно выбрать разделы памяти мышью или ввести их номера, например `1, 3`. Разделы определяются заголовками Markdown `#` и `##`; вложенные заголовки и fenced code blocks остаются внутри раздела. Пустой выбор исключает память. Счётчик проверяет лимит 32 KiB UTF-8 без обрезания текста. `Ctrl+R` обновляет итоговый предпросмотр; `Ctrl+Shift+R` загружает новую ревизию памяти и явно сбрасывает выбор. Подтверждение запуска доступно только для проверенных параметров, а сохранённый снимок не меняется вместе с исходным документом.

В режиме PigADE клавиша `B` открывает «Диалог CLI» выбранной панели; то же действие доступно в палитре. Для Codex/Claude можно явно сохранить UUID беседы, для OpenCode — ID `ses_…`. Привязка версионируется и сохраняет источник: поколение и снимок контекста; подтверждение не запускает CLI. Один текущий ID провайдера нельзя назначить двум логическим сессиям. Наличие беседы у провайдера проверяет сам CLI при продолжении. Для Codex 0.162.1 доступно ручное продолжение по сохранённому UUID; остальные версии и провайдеры пока не поддерживают эту операцию.

Если дерево не помещается в окно, canvas сохраняет минимум 40×8 клеток на панель и показывает полосы прокрутки. Shift+колесо прокручивает canvas, Alt добавляет горизонтальное направление. `Ctrl+Shift+Space`, затем `G` открывает режим прокрутки: стрелки, Home/End и PageUp/PageDown; Enter возвращает к выбранной панели, Escape выходит. Положение сохраняется отдельно для каждой вкладки; focus mode сохраняет положение общей раскладки. При закрытии приложение ждёт записи позиции, а несохранённое состояние показано в строке статуса.

В приложении начните с «Добавить проект», затем создайте воркспейс и запустите CLI кнопкой панели инструментов. `Ctrl+Shift+Space` включает режим PigADE: `P` — команды, `T` — новая вкладка, `1…9` — вкладки, `H/J/K/L` — фокус, `Shift+H/J/K/L` — перемещение, `W` и направление — обмен, `V/S` — split, `R` и стрелки — resize (Enter сохраняет, Escape отменяет), `F` — focus mode, `M` — перенос, `Z/Shift+Z` — undo/redo. Заголовок панели можно перетащить к краю другой для dock или в центр для обмена; границы панелей изменяются мышью. «Сессии» показывает неразмещённые сессии и позволяет вернуть их в текущую вкладку без нового процесса; «Скрыть панель» доступно в палитре. Неизвестный исход запуска блокирует следующий запуск в этом окне, без автоматического retry. Сверка через «Сессии» снимает блокировку только при обнаружении конкретного подтверждённого поколения.

Открыты long-history/24h gates, provider/layout восстановление, полная CLI/platform/accessibility матрица, product-wide performance и сквозной MVP-сценарий. Проверенные результаты, неудачные прогоны и границы каждого измерения находятся в [отчёте cold history](docs/reports/cold-history-integration.md), [отчёте VM reboot](docs/reports/vm-reboot.md), [отчёте runtime/cache](docs/reports/runtime-and-replay-cache.md) и [handoff](docs/AGENT_HANDOFF.md). Синтетический host-тест или работающий accessibility bridge не означают готовность MVP.

В режиме PigADE клавиша `O` или команда «Поколения панели» открывает историю запусков выбранной сессии. Выберите строку мышью либо введите её номер; «текущее» возвращает показ последнего поколения по порядку запуска. Явный выбор сохраняется после перезапуска отдельно от раскладки. Просмотр не запускает CLI; недоступное последнее поколение не подменяется более старым, а исторические процессы не принимают ввод.

Продолжение Codex: выберите завершённую панель → «Диалог CLI» (`B`) → сохраните точный UUID → «Подготовить продолжение» либо найдите `resume` в палитре → проверьте ID, папку и сохранённый контекст → «Продолжить диалог». Процесс запускается в той же панели как новое поколение через durable launch protocol; прежняя история остаётся доступна через `O`. Последнее задание не отправляется повторно. Работающий процесс, неизвестный исход, изменившиеся после просмотра CLI или привязка блокируют старт. Смена уже привязанного диалога требует завершения текущего процесса, чтобы не освободить ID, который ещё используется. Native permission/trust prompts остаются в CLI; PigADE их не подтверждает. Автоматическое продолжение после reboot пока выключено.

Кнопка «История», команда палитры или `Ctrl+Shift+Space`, затем `I` открывает текстовый снимок выбранного поколения. В нём доступны страницы, начало/конец, точный поиск Unicode и копирование выделения/страницы. Архивные и недавние строки читает host; UI не разбирает ANSI повторно. Снимок показывает свой sequence и не меняется от нового вывода. «Обновить» создаёт новый снимок. Просмотр не отправляет ввод в CLI и не запускает процесс. Одновременно host хранит до двух снимков, неиспользуемый снимок истекает через 120 секунд; после истечения используйте «Обновить». Хвост восстановления ограничен 16 MiB: при отсутствии подходящего полного checkpoint показана ошибка, исходная история сохраняется. Это отдельный текстовый режим чтения; основной терминал продолжает отображать клеточную модель.

В истории: Tab переключает поиск/текст, Ctrl+F возвращает к запросу, Enter ищет, F3 показывает следующее совпадение, Shift+F3 начинает поиск заново. PageUp/Down переключают страницы, Ctrl+PageUp/Down — начало/конец, Ctrl+R обновляет снимок, Ctrl+Shift+C копирует страницу. Ctrl+C копирует выделенный текст.
