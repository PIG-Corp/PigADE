# PigADE

В терминале **Ctrl+Shift+C** копирует выделение, **Ctrl+Shift+V** вставляет из буфера независимо от выбранного модификатора панелей. Обычные Ctrl+C и Ctrl+V остаются командами CLI.

Во «Внешнем виде» интерфейс и терминал настраиваются отдельно. **1/2** выбирают тему интерфейса; **3/4/5** — тёмную, светлую палитру терминала или «Как интерфейс». Образец показывает результат; выбор сохраняется после подтверждённой записи. Цвета, явно заданные CLI, сохраняются. Смена палитры не запускает CLI заново и не меняет размер сетки. Те же действия доступны в палитре команд по запросу «палитра».

Колесо над обычным shell прокручивает цветную историю прямо в панели; **Shift+PageUp** открывает её явно, в том числе из TUI. Панель помечается «История» и не принимает ввод в CLI. **PageUp/Down**, стрелки и **Home** перемещают просмотр; **End / Escape** или «К текущему выводу» возвращают живой терминал. Выделение и копирование работают по показанным клеткам. Если CLI включил mouse reporting, обычное колесо получает сам CLI. Снимок истории остаётся неизменным при новом выводе; остальные панели работают независимо. Строки старой ширины не переносятся заново: обрезка справа обозначается, полный текст доступен через отдельный просмотр истории.


Перетащите файлы на работающую панель: PigADE подсветит получателя и покажет точный текст путей перед вставкой. **Ctrl+Enter** подтверждает, **Escape** отменяет, **Ctrl+C** копирует preview, **PgUp/PgDn** прокручивают его. Содержимое файлов не читается и не загружается; вставляются экранированные пути в формате POSIX shell, без добавления Enter. Многострочный текст из буфера также требует просмотра: переводы строк могут выполнить команды в shell. Обычная однострочная вставка остаётся быстрой.

Перенос через **Ctrl+Shift+1…9** или **Ctrl+Shift+Space, M** сохраняет текущую вкладку выбранной. В меню назначения ищите проект, воркспейс или вкладку, выбирайте стрелками и Enter; PgUp/PgDn листают страницы по64 результата, Ctrl+R явно обновляет каталог. Пустая цель получает панель первой, занятая — справа от своей выбранной панели. Архивные и недоступные воркспейсы исключены. Ошибка сохраняет запрос; процесс, его рабочая папка и замороженный контекст при переносе не меняются.

Фокус панели следует за движением указателя без клика, включая вход курсора перед активацией окна. Зажмите выбранный модификатор (по умолчанию **Ctrl**) и **ЛКМ в любой части панели** для переноса, **ПКМ** — для размера. Панель подхватывается сразу, сохраняет точку захвата и вставляется рядом с панелью под курсором; подсветка показывает результат. **Escape** и сброс вне canvas отменяют перенос. Клик с модификатором без движения не меняет раскладку.

Панелями можно управлять как окнами Hyprland: зажмите **Ctrl** (по умолчанию). **Ctrl+Q** закрывает панель, оставляя CLI в фоне; **Ctrl+F** разворачивает её и возвращает раскладку; **Ctrl+стрелки** меняют фокус, **Ctrl+Shift+стрелки** меняют панели местами; **Ctrl+ЛКМ** перетаскивает панель с preview, **Ctrl+ПКМ** меняет размер. Escape отменяет жест. **Ctrl+1…9 / Tab** выбирают вкладки, **Ctrl+Shift+1…9** переносят панель, **Ctrl+Enter** открывает shell. Кнопка **Ctrl ▾** справа сверху позволяет выбрать Ctrl/Alt/Super/Ctrl+Alt или только prefix; выбор сохраняется. Ctrl+C/D/Z/R и незанятые CLI-сочетания продолжают работать; Ctrl+F/Q/стрелки в профиле Ctrl зарезервированы для PigADE. В диалогах действуют обычные команды редактирования. Prefix Ctrl+Shift+Space остаётся доступен. Системные настройки не изменяются. Фокус следует движению курсора над панелью без клика; неподвижный курсор не отменяет переход клавиатурой. При перетаскивании сохраняется точка захвата, перед drop видны сторона вставки и миниатюра итогового дерева с выделенной переносимой панелью; отмена возвращает исходную раскладку.

При закрытии окна PigADE предупреждает о несохранённых черновиках контекста, промптов, профилей и сообщений коммита. Escape возвращает исходный редактор; Tab выбирает действие, Ctrl+Enter явно закрывает без черновиков. Уже отправленные сохранения ожидаются отдельно; через 5 секунд или при ошибке показывается неподтверждённый результат с возможностью вернуться. Закрытие интерфейса не отправляет команду остановки CLI. Эта защита относится к обычному закрытию окна, а не к аварийному завершению процесса.


**Другой CLI:** «Добавить агента» → «Другой CLI…» открывает профиль с названием, абсолютным путём программы и аргументами. Сохраните профиль, выберите его в библиотеке и проверьте короткий обзор команды и рабочей папки; **Ctrl+Enter** запускает, **Escape** отменяет. Создание профиля и подготовка не исполняют программу, включая `--version`. Аргументы передаются отдельными значениями: пробелы разделяют слова, кавычки объединяют текст, shell-подстановок нет. Одинарные кавычки сохраняют текст буквально; двойные поддерживают JSON-экранирование (`\n`, `\r`, `\t`, `\\`, `\"`). Контекст, память, модель и resume PigADE для такой программы отключены; нужные штатные флаги CLI можно указать явно. Старый host без этой возможности не перезапускается автоматически.

**PigADE — Agentic Development Environment:** настольная среда для работы с несколькими CLI-агентами в одном проекте.

Кнопка **Git** в панели вкладки или команда `git` в палитре открывает снимок выбранного воркспейса: ветку, рабочую папку и группы изменений в индексе, рабочей копии, новых файлов и конфликтов. «Обновить снимок» повторяет чтение; PgUp/PgDn/Home/End прокручивают список. Это состояние на момент запроса: CLI может изменить файлы сразу после него. Неполный результат явно помечен, пустой неполный список не означает чистый репозиторий. Просмотр diff по-прежнему только читает: HEAD→индекс, индекс→рабочая копия либо пустой файл→новый файл. Escape возвращает список; Ctrl+R обновляет снимок/сравнение или проверяет неизвестный исход, Ctrl+C копирует показанный diff. Просмотр идёт страницами по200 строк. Бинарные/не-UTF-8, симлинки, подмодули и файлы более256КиБ явно обозначены как недоступные; вывод ограничен128КиБ/2000 строк с предупреждением об обрезке. Конфликтный файл показывается как текст рабочей копии, это не трёхстороннее сравнение.

Для поддерживаемого файла кнопка **Применить индекс** или **Ctrl+S** выполняет ровно одно действие из просмотренного diff: Stage рабочей версии/нового файла или Unstage индексной версии. Перед применением host сверяет билет с точными workspace/project/cwd, HEAD, индексом, файлом и стороной. Он готовит частный кандидат индекса и заменяет индекс через нативный `index.lock` compare-and-swap; рабочий файл не перезаписывается. Обычные Git clean/EOL filters могут запускаться по явному Stage. Нет повторного применения автоматически. Если исход неизвестен, Ctrl+R проверяет его или перечитывает сравнение; **Ctrl+Shift+R** явно подтверждает просмотр состояния Unknown/Unavailable. Уведомление об операции сохраняется после закрытия диалога и перезапуска host. Ограничения: файл256КиБ, индекс8МиБ, до8 билетов на10 минут и4096 долговечных receipts. Sparse/split index, симлинки и конфликтные записи не поддерживаются. Per-file Stage/Unstage и создание обычного коммита доступны; discard/pull/push, Stage All и live watcher ещё не реализованы.

**Создать коммит** в списке Git или **Ctrl+Enter** открывает подготовленные файлы, ветку и поле сообщения. Следующее Ctrl+Enter подтверждает запуск штатного Git с его hooks и настройкой подписи. Изменившийся HEAD/индекс отклоняет устаревший просмотр. Потеря подтверждения оставляет Unknown: проверка и подтверждение просмотра не повторяют commit. После подтверждённого успеха список Git перечитывается. Результат переживает закрытие диалога и перезапуск host; черновик сообщения хранится только до выхода из UI. Текущий срез требует Linux и Git 2.55.0, обычную локальную ветку (включая первый commit), без merge/rebase/conflicts/sparse/split index. Лимиты: индекс8МиБ,512 подготовленных путей, сообщение8192 байта UTF-8,120 секунд. Подробный контракт — [ADR0015](docs/adr/0015-guarded-native-git-commit.md).

Меню **⋯** у проекта, воркспейса и выбранной вкладки открывает переименование. Воркспейс можно убрать в архив и вернуть через «Показать архив» внизу списка; CLI и рабочая папка сохраняются. При возврате host проверяет исходную папку и Git-репозиторий. Меню вкладки также доступно по ПКМ, все действия — через палитру.

Вкладку можно закрыть через её меню **⋯** или команду `close tab` в палитре. Подтверждение показывает название и число панелей; CLI продолжают работать и доступны через «Сессии». Выбирается следующая вкладка того же воркспейса, затем предыдущая; после закрытия последней можно создать новую. Файлы и история CLI сохраняются. Закрытая вкладка не возвращается через undo раскладки. Незавершённый групповой запуск этой вкладки сначала нужно завершить или отменить. **Ctrl+Enter** подтверждает, **Escape** отменяет, **Ctrl+R** сверяет состояние; потерянный ответ не повторяет закрытие автоматически.

Кнопка раскладок рядом с запуском терминала или **Ctrl+Shift+Space, D** открывает библиотеку с миниатюрами. Сохраните геометрию и применяйте её к вкладкам с таким же числом панелей; **undo раскладки** вернёт прежнее размещение, сохранив pane IDs и процессы. Шаблон может оставаться только геометрией или хранить необязательные настройки будущих запусков. Для новой вкладки доступны четыре состава: один агент, implementer + reviewer, два агента + shell и четыре панели. Настройка состава запуска необязательна: без неё обычное создание вкладки и запуск CLI остаются доступны. Перед явным запуском шаблона проверьте имя, число новых процессов, выбранный воркспейс и рабочую папку, а также контекст каждого слота; подготовка сама не создаёт вкладку и не запускает CLI. Запуски продолжаются только по явному действию пользователя, по одному CLI за раз; закрытие диалога приостанавливает оставшиеся шаги, но не останавливает уже работающие процессы. Память, авторизация и conversation ID в шаблон не копируются. Для шаблонов запуска нужен host, объявляющий поддержку схемы; старый host показывает недоступность и не перезапускается автоматически.

В палитре команд ищите размещённые панели по имени, провайдеру, замороженной роли, состоянию, проекту, воркспейсу или вкладке. Страница содержит до64 результатов; «Ещё панели» и «Первые результаты» листают результаты, мышь или стрелки с Enter открывают выбранную панель и переключают на её вкладку. Запрос привязан к текущему диалогу, тексту и ревизии поля, поэтому запоздавший ответ не заменяет результаты нового поиска. Имя панели — локальный alias до128 символов/512 байт UTF-8; управляющие символы и пробелы по краям запрещены, пустое имя сбрасывает alias. Alias меняет отображаемую подпись PigADE, но не заголовок OSC/CLI, контекст, поколение процесса или размещение и не добавляет шаг в undo раскладки. Переход к панели атомарно сохраняет выбор проекта/воркспейса/вкладки и фокусирует её без запуска CLI; сохранённый выбор поколения остаётся на месте. Для переименования и поиска нужен host со schema10 pane-label capability; старый host не перезапускается автоматически.

Остановить CLI можно отдельной командой «Остановить CLI» для выбранной панели или точного поколения в скрытых сессиях. Перед отправкой показывается подтверждение; отмена ничего не меняет. Запрос привязан к зафиксированным UUID сессии и поколения. Он не закрывает панель, не меняет раскладку и не создаёт шаг undo; история остаётся доступной, автоматического возобновления нет. Принятый запрос ещё не означает завершение: PigADE подтверждает его только после наблюдения `exited` для того же поколения. При потерянном ответе UI сверяет состояние только чтением и не повторяет Stop; для `history` или `degraded` процесс остаётся неподтверждённым. На Unix host посылает SIGHUP только верхнему CLI-процессу; дочерние процессы могут продолжить работу. Закрытие окна подтверждения после отправки лишь скрывает наблюдение.

```text
Проект: общий Git-репозиторий и связанные части продукта
└── Воркспейс: задача, агенты, общий промпт, роли и память
    └── Вкладка: сохранённая раскладка
        └── Панели: Claude Code, Codex, OpenCode, shell и другие CLI
```

«Добавить агента» → «Профили агентов» открывает библиотеку повторяемых настроек: название, CLI, роль, инструкции, контекст и необязательные модель/усилие reasoning. Строка профиля показывает запрошенные значения. Пустые поля модели и усилия оставляют настройки CLI по умолчанию. Профиль можно создать отдельно или сохранить из проверки запуска; переключение CLI сохраняет введённые черновые поля. Сохранение не создаёт процесс; запуск сначала показывает снимок текущего воркспейса и точную ревизию профиля, затем требует подтверждения. Изменение или удаление настройки в библиотеке не меняет уже подготовленный план, замороженный argv или работающую сессию. При изменении полей review создаётся самостоятельный снимок, без заявления о неизменённом профиле. Старый host без поддержки engine options отклоняет сохранение непустых значений с объяснением; прежние записи без этих полей загружаются пустыми. Если CLI не поддерживает запрошенную передачу контекста, запуск требует явного выбора без неё. Память, пути, conversation ID, пользовательские конфиги, авторизация и разрешения не копируются и не меняются; роль не ограничивает права. В библиотеке: ↑/↓ и Enter, Ctrl+E — изменить, Delete — подтверждение удаления, Ctrl+R — обновить; в редакторе Ctrl+1/2/3 выбирают CLI, Ctrl+M — контекст, Ctrl+Enter — сохранить.

В библиотеке профилей **Ctrl+P** закрепляет выбранную роль; закреплённые записи показаны первыми. **Alt+↑/↓** и кнопки стрелок меняют порядок внутри закреплённой или обычной группы. После перестановки выбран тот же профиль. Порядок и закрепления сохраняются host отдельно от настроек запуска; они не запускают CLI и не меняют панели. При конфликте используйте Ctrl+R для перечитывания; повторного изменения автоматически нет. Старый host сохраняет прежний порядок и скрывает новые действия.

В настройках панели шаблона кнопка **«Выбрать сохранённый профиль…» / Ctrl+P** открывает поиск по имени или CLI; закреплённые профили идут первыми. **↑/↓, PageUp/PageDown и Enter** выбирают профиль, **Escape** возвращает точный прежний черновик. Выбор заменяет настройки только этой панели копией показанной ревизии; последующее изменение или удаление профиля не меняет сохранённый шаблон. Пользовательские CLI тоже доступны: перед запуском показаны программа, отдельные аргументы и cwd, без настроек контекста/модели. Выбор профиля и сохранение шаблона не запускают процессы.

Проверка запуска и слоты шаблонов также принимают модель и усилие; настройки замораживаются вместе с argv при подготовке. Известные адаптеры: Claude Code 2.1.259 принимает модель и усилие `low`, `medium`, `high`, `xhigh` или `max`; Codex 0.162.1 получает модель и reasoning-строку, а CLI проверяет совместимость с учётной записью и моделью; OpenCode 1.19.3 принимает provider/model, но непустое усилие блокируется. Для неизвестных версий непустые параметры блокируются. Отображённые значения — запрос пользователя: приложение не подтверждает доступность модели для аккаунта или фактическое применение CLI. «Сохранить запуск как профиль» переносит текущие черновые модель и усилие.

Native resume не восстанавливает прежние параметры модели: CLI продолжает диалог со своими текущими настройками, которые пользователь мог изменить; интерфейс показывает это предупреждение. Ни профиль, ни подготовленный снимок не обещают совместимость учётной записи или приём параметров установленным CLI.

**Библиотека промптов** доступна через палитру (`prompts`). Сохраняйте название и текст, редактируйте или удаляйте отдельную запись. В поле инструкций/памяти контекста, запуска, профиля или слота шаблона **Ctrl+Shift+P** открывает библиотеку и вставляет выбранный текст в сохранённую позицию черновика; Ctrl+Z отменяет вставку. **Ctrl+Shift+B** сохраняет выделенный текст (или всё поле) как новый промпт. Без открытого редактора выбор копирует текст для ручной вставки в терминал. Библиотека не отправляет Enter и не запускает CLI. В ней: ↑/↓ и Enter, Ctrl+E — изменить, Delete — подтвердить удаление, Ctrl+R — обновить. Закрытие возвращает исходный черновик; ошибка или конфликт сохранения не стирает правки. До128 активных промптов, текст до32КиБ; удаление из библиотеки не меняет ранее вставленный текст.

Текущая версия: **dev 0.0.1** (`0.0.1-dev`, [VERSION](VERSION)). В native UI доступны Git-проекты, воркспейсы в общей папке или отдельном worktree, вкладки, запуск shell/Claude Code/Codex/OpenCode, палитра команд и редактор версий контекста. Раскладка хранится в host: split, направленный focus/move/swap, перенос между вкладками и воркспейсами, resize с preview, focus mode и undo/redo. Изменение раскладки не запускает новый процесс. Перед запуском доступен просмотр неизменяемого итогового контекста, роли, явно выбранной памяти и метода доставки. Для Claude Code 2.1.259 и Codex 0.162.1 реализованы параметры запуска с контекстом; подтверждение применения моделью отсутствует. OpenCode и неизвестные версии доступны через явный запуск без контекста. Снимок и результат попытки сохраняются для конкретного поколения сессии; редактирование общего документа не меняет работающую сессию. Готового MVP и Linux beta пока нет; оставшиеся критерии SPEC не ослаблены.

Оформление переработано по визуальному ориентиру BridgeMind: компактная общая строка вкладок и запуска, нейтральные поверхности, приглушённый фиолетовый focus и капсульные заголовки терминалов. В заголовке панели доступны split вправо/вниз, focus mode и меню. Боковая панель показывает панели текущей вкладки и автоматически сворачивается в rail при ширине менее 1100 px; кнопка слева сверху сохраняет ручной выбор в текущем окне. [Макеты и промпты imagegen](docs/design/README.md) — отдельные визуальные ориентиры; интерфейс реализован нативными контролами.

**Внешний вид** открывается кнопкой в верхней строке или командой `appearance` в палитре. Выберите тёмную тему клавишей **1** или светлую клавишей **2**; **R** переключает уменьшение движения. **Ctrl+R** перечитывает все настройки, включая размер. Здесь же можно изменить размер терминального шрифта: **+ / =** увеличивают, клавиша **-** уменьшает, **0** возвращает 14 px; видимые кнопки выполняют те же действия. Размер задаётся в диапазоне 10–24 px. Изменения вступают в силу после сохранения настроек. Изменение метрик меняет число строк и столбцов, которое PigADE передаёт через обычный упорядоченный PTY resize; процессы не перезапускаются, дерево раскладки не меняется, а viewport при необходимости прокручивается к видимой области. Переносы строк могут измениться вместе с размером сетки. Пределы диапазона и сброс уже на 14 px — no-op без новой ревизии.

Настройки хранятся в локальном файле с номером ревизии `$XDG_CONFIG_HOME/pigade/appearance.json` (если `XDG_CONFIG_HOME` не задан, используется `$HOME/.config/pigade/appearance.json`). Тема, уменьшение движения и размер терминального шрифта используют одну схему и атомарную проверку ревизии; в старых файлах отсутствующее поле размера читается как 14 px. Настройки приложения не меняют системную тему, масштаб рабочего стола или экранный zoom. Палитра терминала остаётся отдельной: сейчас используется тёмный профиль с фоном `#111317`; светлый профиль терминала не заявлен.

## Что уже можно проверить

Native Rust host запускает реальные процессы через portable-pty. Единственная модель alacritty/VTE находится в host; output/resize/timer events получают sequence и generation, сохраняются с CRC и fsync до публикации клеток. Есть bounded очереди, отдельный input writer, private Unix IPC, durable launch intent/helper/OS identity gate и блокировка неизвестного исхода запуска. После потери host восстановление историческое; процессы и задания сами не повторяются.

Экспериментальный полный checkpoint объединяет Term/Grid и parser/processor: оба экрана, горячую историю, курсоры, modes, tabstops, цвета, частичные UTF-8/CSI/OSC, synchronized buffer и логический timer. Host также архивирует вытесненные строки normal screen как производные записи PIGROW02 в поколенческие сегменты с фиксированным индексом; PIGCP002 привязывает только fsync-подтверждённый индексный корень. Журнал остаётся источником восстановления и не удаляется. Полное восстановление сравнивает горячую модель/parser и каждую холодную запись. Это реализованная основа, а не приёмка длинной истории: текстовый просмотр со страницами и поиском реализован; квоты, глобальный heap budget и long-history gate ещё не завершены.

Нечитаемые или несовместимые журналы показываются отдельным предупреждением восстановления. Они не создают фиктивных живых панелей и не блокируют ввод в исправные сессии. При повреждении типизированного хвоста сохраняются последний корректный кадр и его sequence; исходные файлы остаются без изменений.

[Приложение PigADE](crates/app/README.md) использует GPUI и получает клеточную реплику Rust host. Собственного ANSI-парсера в UI нет. Отдельные контрольные приложения удалены по решению пользователя; история раннего сравнения сохранена в Git. Это рабочее направление разработки, с открытыми gate корректности и платформенной поддержки.

## Сборка и проверки

Проверенная среда: Linux x86_64, Rust/Cargo 1.98.1, C compiler для bundled SQLite. Для UI нужны системные библиотеки GPUI из его официального Linux setup. Другие compiler/distro/platform версии не сертифицированы. Cargo.lock в корне и crates/app/Cargo.lock фиксируют зависимости host и UI. Лицензия продукта пока не выбрана; лицензии vendored компонентов сохранены, GPL terminal-код Zed не заимствован.

```sh
cargo build --release --workspace --bins --examples
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
python3 scripts/check-version.py
```

Для UI: `crates/app/bootstrap.sh build --locked` и `crates/app/bootstrap.sh test --locked`. Bootstrap проверяет SHA-256 закреплённого GPUI archive и применяет [точный профиль X11 IME](crates/app/patches/gpui-x11-ime/) с проверкой исходных/итоговых хешей; неизвестное состояние кэша останавливает сборку. Он только собирает код, без открытия окон. `bash scripts/check.sh` выполняет проверки host/model workspace. Полные vendor/regression-команды и фактические результаты находятся в patch notes и отчётах.

## Запуск Rust host

Без systemd, в отдельном терминале:

```sh
mkdir -p "${XDG_STATE_HOME:-$HOME/.local/state}/pigade/dev-0.0.1"
target/release/pigade-session-host serve "${XDG_STATE_HOME:-$HOME/.local/state}/pigade/dev-0.0.1"
```

Управляемый user service, отдельный от UI:

```sh
bash scripts/start-dev-host.sh
systemctl --user status pigade-dev-host
```

Пример реального shell в host:

```sh
target/release/pigade-session-host launch \
  "${XDG_STATE_HOME:-$HOME/.local/state}/pigade/dev-0.0.1/host.sock" \
  "$PWD" /usr/bin/bash --noprofile --norc
```

Для длинного пути состояния можно указать отдельный короткий приватный каталог: `serve STATE_DIRECTORY --runtime PRIVATE_DIRECTORY`. Каталог runtime должен принадлежать пользователю и иметь режим 0700; UI подключается к `PRIVATE_DIRECTORY/host.sock`. Блокировки состояния и runtime предотвращают замену endpoint другого работающего host. Данные остаются в STATE_DIRECTORY.

`list SOCKET`, `request SOCKET JSON_COMMAND`, `replay JOURNAL` и `verify-recovery JOURNAL` — диагностический интерфейс. Input/resize/stop требуют точные session/generation UUID. `replay` не исполняет команды и terminal side effects. `verify-recovery` сравнивает полные модели полного replay и checkpoint+tail; нужен завершённый или неизменяемый журнал. Историческая панель не принимает ввод. Версия: `target/release/pigade-session-host --version`.

Остановка user service завершает его дочерние процессы; это отдельное явное действие: `systemctl --user stop pigade-dev-host`. Закрытие UI отличается от остановки host. После сбоя неизвестные launch intents остаются заблокированы; автоматического нового shell/resume нет.

## Измерения и ограничения

```sh
python3 scripts/hardware-manifest.py
python3 scripts/run-component-benchmark.py \
  --directory "${XDG_STATE_HOME:-$HOME/.local/state}/pigade/benchmarks"
python3 scripts/probe-cli-pty.py \
  --directory "${XDG_STATE_HOME:-$HOME/.local/state}/pigade/probes"
```

Benchmark требует durable filesystem, отклоняет tmpfs и измеряет компоненты без GPU/UI; его числа не равны input-to-present. CLI probe запускает только `--version`/`--help` через реальный PTY, не выполняет AI-задачи и не сертифицирует resume. Нагрузочная проверка: `python3 scripts/stress-pty.py --directory /absolute/durable/path`. Она не открывает UI и не является input-to-present benchmark. [Текущий отчёт о проверках](docs/reports/verification-0.0.1-dev.md) содержит результаты и точные пробелы.

Сырые результаты: [benchmarks/results](benchmarks/results), [CLI matrix](docs/compatibility/CLI.md), [ADR](docs/adr), [отчёты](docs/reports).

После сборки host и UI приложение запускается как `crates/app/target/debug/pigade-app`: оно подключается к локальному host или запускает его самостоятельно. Состояние хранится в `${XDG_STATE_HOME:-$HOME/.local/state}/pigade/dev-0.0.1`, сокет — в приватном подкаталоге `${XDG_RUNTIME_DIR}` либо рядом с состоянием. `PIGADE_HOST_BINARY` позволяет явно выбрать бинарник host. Явное подключение без автоматического старта: `crates/app/target/debug/pigade-app /absolute/state/host.sock`. Закрытие окна не завершает host. Автоматизация окон/ввода на активном desktop запрещена; platform tests требуют изолированного compositor/VM.

Редактор контекста поддерживает курсор, выделение мышью и Shift+стрелками, навигацию по словам, копирование/вырезание/вставку и ограниченный undo/redo. Enter добавляет строку в многострочном поле; Ctrl+Enter сохраняет ревизию или подтверждает запуск. Tab/Shift+Tab переключают поля. Режим PigADE, затем `E` открывает контекст воркспейса, `Shift+E` — проекта. Ответ на сохранение сохраняет набранный после отправки черновик; незавершённый IME-ввод не попадает в запуск.

Перед запуском можно выбрать разделы памяти мышью или ввести их номера, например `1, 3`. Разделы определяются заголовками Markdown `#` и `##`; вложенные заголовки и fenced code blocks остаются внутри раздела. Пустой выбор исключает память. Счётчик проверяет лимит 32 KiB UTF-8 без обрезания текста. `Ctrl+R` обновляет итоговый предпросмотр; `Ctrl+Shift+R` загружает новую ревизию памяти и явно сбрасывает выбор. Подтверждение запуска доступно только для проверенных параметров, а сохранённый снимок не меняется вместе с исходным документом.

В режиме PigADE клавиша `B` открывает «Диалог CLI» выбранной панели; то же действие доступно в палитре. Для Codex/Claude можно явно сохранить UUID беседы, для OpenCode — ID `ses_…`. Привязка версионируется и сохраняет источник: поколение и снимок контекста; подтверждение не запускает CLI. Один текущий ID провайдера нельзя назначить двум логическим сессиям. Для Codex 0.162.1 доступно ручное продолжение по сохранённому UUID. Для OpenCode 1.19.3 — по точному ID `ses_…`, без повторной отправки задания или контекста PigADE. Перед подготовкой и запуском host через локальный API OpenCode проверяет существование диалога и совпадение его сохранённой папки с исходной; диалоги с native workspace routing отклоняются. Проверка идёт в отдельном worker и не блокирует терминалы. Унаследованные `OPENCODE_CONFIG_CONTENT` или `OPENCODE_WORKSPACE_ID` отключают расширенный адаптер OpenCode с объяснением; обычный запуск CLI остаётся доступен. Другие версии и Claude пока не поддерживают эту операцию. Ошибка resume не создаёт новый диалог автоматически.

Если дерево не помещается в окно, canvas сохраняет минимум 40×8 клеток на панель и показывает полосы прокрутки. Shift+колесо прокручивает canvas, Alt добавляет горизонтальное направление. `Ctrl+Shift+Space`, затем `G` открывает режим прокрутки: стрелки, Home/End и PageUp/PageDown; Enter возвращает к выбранной панели, Escape выходит. Положение сохраняется отдельно для каждой вкладки; focus mode сохраняет положение общей раскладки. При закрытии приложение ждёт записи позиции, а несохранённое состояние показано в строке статуса.

В приложении выберите «Открыть папку» для существующего Git-репозитория или «Создать проект» для новой папки с Git. Первый воркспейс «Основной» и вкладка Development создаются автоматически; CLI сам не запускается. «Терминал» открывает shell одним действием. «Добавить агента» показывает установленные CLI; выбор сразу открывает CLI без передачи общего контекста. Необязательная форма роли, памяти и доставки доступна через команды «Настроить запуск Claude Code / Codex / OpenCode» в палитре. Проверка CLI не блокирует действия. Кнопки открытия и создания проекта всегда доступны внизу списка слева; «+» рядом с проектом создаёт следующий воркспейс с названием задачи и явным выбором общей папки или отдельного worktree. Для worktree у нового репозитория сначала нужен первый commit; PigADE не создаёт его за пользователя. «Панели» открывает действия с текущей раскладкой, историей и переносом. `Ctrl+Shift+Space` включает режим PigADE: `P` — команды, `Shift+O` — открыть папку, `N` — воркспейс, `Shift+N` — проект, `Enter` — shell, `Shift+Enter` — настроить запуск shell, `T` — новая вкладка, `1…9` — вкладки, `H/J/K/L` — фокус, `Shift+H/J/K/L` — перемещение, `W` и направление — обмен, `V/S` — split, `R` и стрелки — resize (Enter сохраняет, Escape отменяет), `F` — focus mode, `M` — перенос, `Z/Shift+Z` — undo/redo. Активная панель следует за курсором без клика. Ctrl+ЛКМ сразу вынимает панель из дерева (drag за заголовок — после10px); она следует за курсором и вставляется рядом с целевой по правилам Dwindle, без обмена в центре. Подсветка показывает сторону вставки; над зазором выбирается ближайшая панель; сброс вне canvas отменяет перенос. В focus mode перенос временно показывает остальные панели; Escape возвращает исходный режим и раскладку. Для переноса на другую вкладку удерживайте Ctrl и перетащите панель на её название: подсветка и миниатюра показывают результат; отпускание переносит существующую сессию и открывает эту вкладку. Работает и с пустой вкладкой; в занятой вставляет справа от выбранной панели. Escape отменяет, undo возвращает обе раскладки. Ctrl+ПКМ и границы панелей меняют размер. «Сессии» показывает неразмещённые сессии и позволяет вернуть их в текущую вкладку без нового процесса; «Скрыть панель» доступно в палитре. Неизвестный исход запуска блокирует следующий запуск в этом окне, без автоматического retry. Сверка через «Сессии» снимает блокировку только при обнаружении конкретного подтверждённого поколения.

Открыты long-history/24h gates, provider/layout восстановление, полная CLI/platform/accessibility матрица, product-wide performance и сквозной MVP-сценарий. Проверенные результаты, неудачные прогоны и границы каждого измерения находятся в [отчёте cold history](docs/reports/cold-history-integration.md), [отчёте VM reboot](docs/reports/vm-reboot.md), [отчёте runtime/cache](docs/reports/runtime-and-replay-cache.md) и [handoff](docs/AGENT_HANDOFF.md). Синтетический host-тест или работающий accessibility bridge не означают готовность MVP.

В режиме PigADE клавиша `O` или команда «Поколения панели» открывает историю запусков выбранной сессии. Выберите строку мышью либо введите её номер; «текущее» возвращает показ последнего поколения по порядку запуска. Явный выбор сохраняется после перезапуска отдельно от раскладки. Просмотр не запускает CLI; недоступное последнее поколение не подменяется более старым, а исторические процессы не принимают ввод.

Продолжение Codex: выберите завершённую панель → «Диалог CLI» (`B`) → сохраните точный UUID → «Подготовить продолжение» либо найдите `resume` в палитре → проверьте ID, папку и сохранённый контекст → «Продолжить диалог». Процесс запускается в той же панели как новое поколение через durable launch protocol; прежняя история остаётся доступна через `O`. Последнее задание не отправляется повторно. Работающий процесс, неизвестный исход, изменившиеся после просмотра CLI или привязка блокируют старт. Смена уже привязанного диалога требует завершения текущего процесса, чтобы не освободить ID, который ещё используется. Native permission/trust prompts остаются в CLI; PigADE их не подтверждает. Автоматическое продолжение после reboot пока выключено.

Кнопка «История», команда палитры или `Ctrl+Shift+Space`, затем `I` открывает текстовый снимок выбранного поколения. В нём доступны страницы, начало/конец, точный поиск Unicode и копирование выделения/страницы. Архивные и недавние строки читает host; UI не разбирает ANSI повторно. Снимок показывает свой sequence и не меняется от нового вывода. «Обновить» создаёт новый снимок. Просмотр не отправляет ввод в CLI и не запускает процесс. Одновременно host хранит до двух снимков, неиспользуемый снимок истекает через 120 секунд; после истечения используйте «Обновить». Хвост восстановления ограничен 16 MiB: при отсутствии подходящего полного checkpoint показана ошибка, исходная история сохраняется. Это отдельный текстовый режим чтения; основной терминал продолжает отображать клеточную модель.

В истории: Tab переключает поиск/текст, Ctrl+F возвращает к запросу, Enter ищет, F3 показывает следующее совпадение, Shift+F3 начинает поиск заново. PageUp/Down переключают страницы, Ctrl+PageUp/Down — начало/конец, Ctrl+R обновляет снимок, Ctrl+Shift+C копирует страницу. Ctrl+C копирует выделенный текст.
